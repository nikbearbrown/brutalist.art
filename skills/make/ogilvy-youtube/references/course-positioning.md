# Course positioning for YouTube metadata

Use this reference only for films sourced from one of these course directories.
The shared teaching sequence is **Predict → Build It → Use It → Ship It →
Verify**. That sequence is a channel-level differentiator, but it should appear
in copy only when the film demonstrates part of it. Never paste the sequence
into every description as boilerplate.

Course films are optional learning artifacts. A film folder or render is not
proof of publication, institutional endorsement, assignment completion, or a
validated research result. Preserve the source course's cautions and actual
status.

## INFO 6205 — Program Structure and Algorithms

**Directory:** `info-6205-algorithms`

**Promise:** Make algorithms executable and defensible: state the contract,
implement the mechanism, trace a worked instance, argue correctness and cost,
then check observed behavior without mistaking tests or animation for proof.

**Audience outcome:** The viewer should be able to explain why an algorithm
works, when its assumptions hold, what it costs, and what evidence would expose
a bad implementation.

**Proof patterns:** pseudocode, representation invariants, recurrence or
exchange arguments, certificates, boundary tests, small-instance checks,
runtime observations under a stated workload.

**Useful vocabulary:** algorithms and data structures, Python algorithms,
correctness proof, complexity analysis, worked example, graph algorithms,
dynamic programming, greedy algorithms, divide and conquer, network flow,
randomized algorithms, caching.

**Avoid:** “tests prove correctness,” “animation proves the algorithm,” or an
empirical timing claim presented as an asymptotic bound.

## INFO 7375 — Branding and AI

**Directory:** `info-7375-branding-and-ai`

**Promise:** Build one running brand whose promise, audience, identity, voice,
touchpoints, evidence, and handoff can be inspected. AI drafts and implements;
the human owns creative direction, audience judgment, evidence, and commitments.

**Audience outcome:** The viewer should be able to make a sharper brand decision
and show the evidence behind it—not merely generate a logo or polished artifact.

**Proof patterns:** audience choice, deliberate exclusions, positioning,
creative specimens, evidence ledgers, version history, feedback, measurement
with denominators and causal limits, portfolio-as-product.

**Useful vocabulary:** branding and AI, creative engineer, brand strategy,
brand positioning, brand voice, audience research, visual identity system,
portfolio as product, brand evidence, AI-assisted branding, Ideate Build Brand
Ship.

**Avoid:** invented interviews, audience fit inferred from synthetic personas,
local name checks presented as trademark clearance, mock results presented as
market impact, or a validator presented as proof of creative effectiveness.

## INFO 7375 — Computational Skepticism for AI

**Directory:** `info-7375-computational-skepticism-for-ai`

**Promise:** Turn plausible AI claims into predictions, assumptions, break tests,
and inspectable evidence. Make every sentence no stronger than what the result
supports.

**Audience outcome:** The viewer should be able to challenge an AI output using
calibration, provenance, robustness, counterexamples, fairness trade-offs,
agent traces, or explicit approval conditions.

**Proof patterns:** falsification tests, probability and calibration, missingness
and provenance, distribution shift, counterexamples, group metrics, agent state,
trace inspection, replication, uncertainty language.

**Useful vocabulary:** computational skepticism, AI validation, AI audit,
calibration, data provenance, robustness testing, explainability limits, AI
bias, fairness metrics, agent evaluation, evidence-based AI.

**Avoid:** equating explanation with causation, confidence with correctness,
finite tests with universal proof, or a fairness metric with a uniquely correct
moral choice.

## INFO 7375 — Conducting AI

**Directory:** `info-7375-conducting-ai`

**Promise:** Teach the supervisory work that turns AI output into a defensible
professional contribution: judge plausibility, formulate the problem, make
handoffs explicit, interpret context, integrate evidence, and reopen decisions
when the problem changes.

**Audience outcome:** The viewer should be able to supervise an AI workflow,
name what only a human decision can settle, and produce an accountable Memo B
rather than forwarding an AI-produced Memo A.

**Proof patterns:** judgment recorded before lookup, solve–verify asymmetry,
substantive reframing, evidence and authority at handoffs, dependency checks,
re-engagement records, supervisory analysis, gap account.

**Useful vocabulary:** Conducting AI, AI supervision, plausibility audit,
problem formulation, tool orchestration, explicit handoffs, interpretive
judgment, executive integration, human oversight, supervisory analysis.

**Avoid:** “human in the loop” as an unexplained slogan, a checker presented as
a replacement for judgment, or universal claims about AI limits unsupported by
the film.

## INFO 7375 — Irreducibly Human

**Directory:** `info-7375-irreducibly-human`

**Promise:** Design and defend the division of labor between people and AI across
pattern recognition, embodied feedback, relationships, supervision, causality,
collective judgment, values, and practical wisdom.

**Audience outcome:** The viewer should be able to decide what to delegate,
what understanding must be retained to check the work, and where observation,
consent, relationship, authority, or normative choice remains necessary.

**Proof patterns:** baselines and interventions, embodied measurements, real
human handoffs, calibration, causal and counterfactual questions, independence
and correlated errors, preserved dissent, explicit value choices.

**Useful vocabulary:** human AI division of labor, irreducibly human, AI
delegation, cognitive offloading, embodied intelligence, human relationships and
AI, AI supervision, causal reasoning, collective intelligence, human judgment.

**Avoid:** treating the taxonomy as a timeless capability benchmark, simulated
social language as a real relationship, synthetic data as exposure evidence, or
human judgment as automatically correct.

## INFO 7375 — Prompt Engineering for Generative AI

**Directory:** `info-7375-prompt-engineering-for-generative-ai`

**Promise:** Build the mechanisms behind prompting and agentic work before
relying on managed tools: sampling, prompt contracts, evaluation, bounded loops,
permissions, retrieval, MCP, planning, tool verification, memory, multi-agent
coordination, and approval gates.

**Audience outcome:** The viewer should be able to inspect, test, and supervise a
Claude workflow rather than collect generic prompt recipes.

**Proof patterns:** held-out prompt evaluation, explicit action surfaces, agent
traces and stop conditions, path policies, lexical retrieval, minimal MCP,
reviewed plans and diffs, tool evidence matrices, versioned memory, proposals
bound to approvals.

**Useful vocabulary:** prompt engineering, Claude Code tutorial, prompt
evaluation, prompt contracts, agent loop, tool permissions, context retrieval,
MCP server, plan before acting, tool-use verification, multi-agent systems,
human approval gates.

**Avoid:** generic “best prompt” claims, Claude Code access conflated with API
credits, offline fixtures presented as live model evidence, prompting conflated
with training, or independent university teaching presented as Anthropic
certification.

## Choosing course labels and keywords

- Put the concept before the course code in the title. The course code may be a
  suffix when students need it, but it must not consume the opening hook.
- Mention Northeastern University only when the source film/course metadata does
  so and never imply university endorsement of a result or external product.
- Use `INFO 6205` or `INFO 7375` in keyword tags only for actual course films.
- Prefer the lesson's mechanism and outcome over broad category tags. “Prompt
  contract evaluation” is stronger than “generative AI”; “Gale–Shapley stability
  certificate” is stronger than “computer science.”
- When a film crosses courses, choose one primary promise. Add the other course's
  vocabulary only where its distinct check is visibly used in the film.
